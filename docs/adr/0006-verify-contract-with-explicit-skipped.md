# ADR-0006: verify 机器验收合同;跳过的检查显式 SKIPPED

- 状态:Accepted(2026-09-01)
- 关联:ADR-0004(冻结数据集 sha256)、ADR-0005(中文安全文案);报告 §4.4、§6.3、§8.5 #6

## 背景

参照物最有原创性的工程想法:交付物完整性被机器验收——`verify.py` 检查必需文件、对研究报告做安全文案**字符串断言**(缺一即 `SystemExit`)、跑全量 pytest(§4.4)。已知盲区:公开 checkout 上整块课件检查被静默跳过,「make check 通过」≠「全部检查通过」(§6.3,风险 #6)。

## 决策

1. 我们的 `verify.py` 包含四类检查:① 必需文件清单;② 研究报告中文安全文案字符串断言;③ 冻结数据集 manifest/sha256 校验;④ 全量 pytest。
2. **任何被跳过的检查必须显式打印 `SKIPPED` 及原因**,禁止静默通过——这是对参照物的第一处有意改进。
3. contract tests 只为我们真实拥有的契约写(安全文案、manifest、投资门指纹、验收合同);不复刻参照物的课件合同测试(`docs/v2` 章节矩阵那套,结构上不存在,§4.3)。
4. 「构建前端」与「验证产品」拆成两个入口:verify 不依赖 Node(与参照物 `verify.py` 会联网跑 npm 不同,§8.5 #9)。

## 后果

- 错层分工固定:票内行为由 pytest 锁,交付物完整性由 verify 锁,不做票级断言(避免与 TDD 重复)。
- 安全文案的任何措辞改动 = 契约变更,verify 与测试必须同票更新。
- 「verify 全绿」的含义从此是诚实的:要么跑了,要么明说跳了。
