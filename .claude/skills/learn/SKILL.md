交互式学习一课:以「站」为单位走读已实现的课程,面向 Python 初学者,中文授课。参数为课号(课 N 的教材是 `docs/course/NN-*.md`,对应票 #N+1);缺省时列出已有教材的课让用户选,或接续 `docs/course/STUDY.md`(若存在)最后一条的下一课。

## 0. 前提

只能学**已实现**的课——教材 `docs/course/NN-*.md` 存在即已实现。目标课尚未实现时,不开始走读,建议用户先 `/lesson <票号>` 实现:先造机器,再学机器。

## 1. 装载

读该课教材全文、它产出的代码、票中点名的 ADR 与 CONTEXT.md 相关行。**数字断言先验证再教学**:测试条数、命令的预期输出,要自己跑过一遍(教材里的计数会过期,如后来新增的回归锁)。完成判据:教材、代码、验收合同都在上下文,且每条将写给用户的「预期输出」都被验证过或明确标注为预测。

## 2. 排路线

把本课切成 5–7 站,表格呈现:每站主题 + 顺带要教的 Python 知识点(初学者没见过的惯用法优先入列)。最后一站固定为「通关 + 概念卡片 + 你问我答」。给出路线图即停,等用户推进——**节拍由用户控制**(「进第 N 站」才前进;插问随时答)。

## 3. 逐站教学

每站一条消息,讲解 + 动手 + 预告下站:

- **讲解**引用仓库真实文件与代码(片段 ≤30 行),出处照写(ADR 编号 / 研报 § / 票 #),措辞用 CONTEXT.md 词汇表。遇到 Python 惯用法就地拆开讲——dataclass、Protocol、生成器、pytest 夹具这类,默认学习者没见过。
- **动手**每站至少一条可在会话里跑的命令(`!` 前缀),附逐行预期输出。本仓 Windows/GitBash 适配:`python`(非 `python3`);中文要可读加 `-X utf8`;PYTHONPATH 用引号包住的分号形式 `'src;tests'`。demo 脚本放仓库根 `demo_lessonNN.py`,**先自跑验证再交付**,并声明「教学草稿、可删、不入库」。
- **判卷**凡可手算的(记账、费用、口径),先出题让用户算、再由引擎或测试对账;用户答「不知道」就直接给答案——用「预测 → 跑 → 对账」代替冷考。判出的分歧(如口径之差)是最高级的教材,展开讲。
- 用户跳过动手命令不阻拦,收官时汇成「补跑清单」。输出乱码时一句话点破(编码显示问题,数值照读),同一会话只解释一次。

## 4. 收官站

四件套:**全课一张图**(站点逻辑链)、**概念卡片表**(每张一句话,带走即用)、**通关验收清单**(已跑的标 ✅,未跑的给命令与预期,含教材验收练习的 Windows 适配版)、**下一步分叉**(继续 `/learn` 下一课,或 `/lesson` 实现下一课)。然后开放你问我答,直到用户无疑问。

## 5. 记录

问用户要不要在 `docs/course/STUDY.md` 追加一行(课号 + 日期),用作下次缺省接续;不要则完全跳过,学习过程零仓库写入。完成判据(全技能):路线全站走完、验收清单已交付、下一步方向已给出。
